# Vale Lab Compounding Build Queue

The rule: finish one useful system, then reuse what it taught us in the next. New projects should inherit infrastructure, methods, data structures, and lessons from earlier work.

## NOW — Fireblade Engine
Goal: complete a printable Volume 1 while proving a sequence-first multimedia production workflow.

Reusable outputs expected:
- structured canon / source authority system
- reusable asset catalog
- character/location/prop reference locking
- sequence manifests
- panel-level revision model
- visual QA workflow
- batch generation/review workflow
- local + GitHub project handoff pattern

Exit condition:
A complete readable Volume 1 draft exists and the system can produce a new sequence from structured inputs without panel-by-panel babysitting.

## LATER — Dream Forensics research/story project
Research lane + Wolves/Silas story concept.

Core idea:
A system does not replay dreams faithfully. It reconstructs confidence-weighted evidence from neural signals, then a generative model fills gaps. The reconstruction may itself contaminate later memory.

Research questions:
- mental imagery decoding fidelity
- dream content decoding
- generative-prior contamination
- memory reconsolidation after viewing reconstructions
- cross-subject neural decoding
- ethics/evidentiary misuse

Potential story value:
The uncertainty between recovered signal and generated completion becomes the central danger.

## Backlog rule
New ideas go into backlog unless they clearly:
1. accelerate the current build,
2. reuse an existing system,
3. generate near-term evidence/revenue/output,
4. or are uniquely time-sensitive.

Do not abandon the current milestone for a more exciting idea.
